# AutoDM

## Project Summary
AutoDM is a local-first, browser-based automated Dungeon Master application. The frontend is Angular 22 with TypeScript; the backend is Java 21 Spring Boot with a Maven Wrapper and a REST API; persistence is local SQLite via Spring Data JPA. The application manages campaigns, player characters, world/NPC/quest/faction/item data, turn-based encounters, and a deterministic, extensible Dungeon Master engine loop, all stored locally with no external dependencies.

## Architecture
- **Frontend:** Angular (Version 22)
- **Backend:** Spring Boot / Java (Version 21)
- **Database:** SQLite
- **Build Tool:** Maven Wrapper + npm
- **Deployment:** local-only

## Assumptions
- A Java 21 JDK and a Node.js runtime compatible with Angular 22 are available on the local machine.
- The Maven Wrapper can be generated with `mvn -N wrapper` or provided into the server directory.
- A SQLite JDBC driver (for example xerial sqlite-jdbc) is usable with Spring Boot and Spring Data JPA.
- The human operator will start the backend and frontend locally and perform final manual acceptance.
- No internet connection is required during development or normal gameplay.
- Generic fantasy RPG mechanics are used instead of any copyrighted proprietary rulebook.
- A future local or remote language-model provider can be added behind the Dungeon Master abstraction without rewriting the application.
- The Angular frontend and Spring Boot backend are run as two local processes, with the backend acting as the authoritative source of campaign state.

## Constraints
- Angular 22 and Java 21 must be used exactly; no downgrade, substitution, or reinterpretation of versions.
- Deployment is local-only; no cloud, SaaS, Firebase, or external storage is used.
- No external LLM or AI provider is used in the initial implementation.
- SQLite is the authoritative persistence store; the entire application state must not be stored as one opaque JSON blob.
- Random results and dice rolls must be generated by backend game logic, not trusted from the browser.
- Automated testing is not part of completion authority; final acceptance is performed manually by the human operator.
- No virtual tabletop, real-time multiplayer, voice chat, 3D graphics, user accounts, or payment systems are included.
- Random results and dice rolls must be generated by backend game logic, not trusted from the browser.

## Running the Application Locally

The application runs as two distinct local processes.

### Backend (Spring Boot Server)
Ensure you have a Java 21 JDK installed.
Navigate to the `server/` directory and run the application using the Maven Wrapper:
```bash
cd server
./mvnw spring-boot:run
```
*(On Windows, use `mvnw.cmd spring-boot:run`)*

### Frontend (Angular Client)
Ensure you have a Node.js runtime compatible with Angular 22 installed.
Navigate to the `client/` directory, install dependencies, and start the development server:
```bash
cd client
npm install
npm start
```

The frontend will be available at `http://localhost:4200/` (or the default Angular port) and will communicate with the backend REST API locally.
